# Deploying Prompt2Resume

Backend (Express + Prisma) runs on **Render**. Frontend (Next.js) runs on
**Vercel**. Database is **Supabase Postgres** (Prisma owns the schema).

> **Deploy order:** backend first (to get its URL) → frontend → then come back
> and set the backend's `FRONTEND_URL` to the Vercel domain.

---

## 0. Prerequisites

- Repo pushed to GitHub.
- Supabase project ready. Copy the **Session pooler** connection string from
  Supabase → **Connect → Session pooler** (port `5432`). It looks like:
  ```
  postgresql://postgres.yyvnfpgskfovwtsbtavv:<PASSWORD>@aws-0-<region>.pooler.supabase.com:5432/postgres
  ```
  Do **not** use the direct `db.<ref>.supabase.co` host — it is IPv6-only and
  fails on Render.

---

## 1. Backend → Render

### Option A — Blueprint (uses `render.yaml`, recommended)

1. Render dashboard → **New + → Blueprint** → select this repo.
2. Render reads `render.yaml` and creates the `prompt2resume-api` service.
3. When prompted, fill the secret env vars (see table below). `JWT_ACCESS_SECRET`
   and `JWT_REFRESH_SECRET` are generated automatically.
4. Click **Apply** to deploy.

### Option B — Manual

1. **New + → Web Service** → connect repo.
2. Root Directory `backend` · Build `npm install && npm run setup` · Start
   `npm start` · Health Check Path `/api/health`.
3. Add the env vars below.

### Backend environment variables

| Key | Value | Notes |
|-----|-------|-------|
| `NODE_ENV` | `production` | **Required** — enables `SameSite=None; Secure` cookies + trust proxy |
| `DATABASE_URL` | Supabase Session pooler URI | port 5432 |
| `JWT_ACCESS_SECRET` | long random string | auto-generated by Blueprint |
| `JWT_REFRESH_SECRET` | long random string | auto-generated by Blueprint |
| `ADMIN_EMAIL` | your admin email | seeded as admin on `npm run setup` |
| `ADMIN_PASSWORD` | strong password | |
| `AI_API_KEY` | server-side AI key | users never supply their own |
| `AI_MODEL` | `claude-opus-4-8` | optional; this is the default |
| `FRONTEND_URL` | Vercel URL(s) | set in step 3 (comma-separated allowed) |

4. After deploy, verify:
   ```
   https://<your-api>.onrender.com/api/health  →  { "ok": true, ... }
   ```

---

## 2. Frontend → Vercel

1. Vercel → **Add New → Project** → import the same repo.
2. **Root Directory:** `frontend` (Framework auto-detects as Next.js).
3. Environment variable:
   | Key | Value |
   |-----|-------|
   | `NEXT_PUBLIC_API_URL` | `https://<your-api>.onrender.com` |
4. Deploy. Note the resulting domain, e.g. `https://prompt2resume.vercel.app`.

---

## 3. Close the loop (CORS + cookies)

1. In Render, set **`FRONTEND_URL`** to your Vercel domain. To also allow Vercel
   preview deployments, pass a comma-separated list (the CORS allowlist supports it):
   ```
   FRONTEND_URL=https://prompt2resume.vercel.app,https://prompt2resume-git-main-<you>.vercel.app
   ```
2. **Manual Deploy → Deploy latest commit** on Render so the new value applies.
3. Open the Vercel URL → register → log in. The auth cookie must persist across
   the cross-domain request — this relies on `NODE_ENV=production` (cookies become
   `SameSite=None; Secure`) and `trust proxy`, both already wired in.

---

## 4. Make yourself admin

`npm run setup` seeds an admin from `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Log in with
those, then approve other users from the **Admin** page.

---

## Troubleshooting

- **Login "works" then immediately logged out / 401 loop** → cookies aren't being
  stored. Confirm `NODE_ENV=production` on Render and that the Vercel origin is in
  `FRONTEND_URL`. Cross-domain cookies require HTTPS on both ends (Vercel + Render
  are both HTTPS by default).
- **CORS error in browser console** → the request Origin isn't in `FRONTEND_URL`.
  Add it (comma-separated) and redeploy the backend.
- **DB connection errors / IPv6** → you're using the direct `db.<ref>` host. Switch
  `DATABASE_URL` to the Session pooler URI (port 5432).
- **First request very slow (~30–50s)** → Render free tier cold start. Upgrade the
  plan or hit `/api/health` to warm it.
- **Schema changes not reflected** → `npm run setup` runs `prisma db push` each
  deploy. If a column is missing, trigger a redeploy or run `npm run db:push`.
